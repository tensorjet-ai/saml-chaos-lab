# Known limitations — v0.1.0 / Catalog 2.0.0

- SAML Web Browser SSO only; no OIDC, SCIM, SLO, encryption, or IdP-initiated support.
- Catalog 2.0.0 adds XML Signature Wrapping, canonicalization, XML parser, and identity-selection probes. Results depend on the target parser and SAML library; a passing probe does not certify the target.
- The Node-SAML and Samlify regression checks verify that these probes do not resolve to the exact spoofed identity. A library may still accept a transformed NameID as a different composite string.
- Outcome scoring depends on configured URL and optional DOM signals; ambiguous UI is inconclusive.
- Certificate rollover behavior varies by vendor and is reported as compatibility evidence, not a universal security failure.
- Local development uses an envelope master key. Production deployment requires a cloud KMS adapter and network egress policy supplied by the hosting platform.
- Invite-token access is the included hosted assisted-launch boundary. GitHub OAuth and public self-service account management are deferred.
- PDF is generated by printing the standalone HTML report; native PDF rendering is deferred.
- This is a readiness report, not SAML certification, penetration-test certification, compliance attestation, or legal assurance.
